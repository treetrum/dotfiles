# General Instructions

-   Always use [conventional commits](https://www.conventionalcommits.org/en/v1.0.0/) for all Git commits.
-   Never commit or push changes without asking the user for confirmation first.
-   Keep code comments succinct and terse.
-   For any GitHub interaction (opening/editing PRs, reading remote repos, issues, comments), use the `gh` CLI. Do not use the web UI or raw API calls when a `gh` command exists.
-   Write PR descriptions that are short and high-level: open with a one-sentence summary of the intent and impact, followed by a few high-level bullet points for the notable details. Do not enumerate every file or change.
